[P.03] // ÉTUDE DE CAS

DrawMatch

Deux joueurs dessinent un mot, « Pen », une IA TensorFlow, doit le deviner en temps réel. Projet d'équipe, licence GPL v3.

  • 2joueurs par salle
  • 7mots par partie
  • 345mots reconnus
  • 28×28pixels en entrée du modèle

[01] // PROBLÈME

Un Pictionary où c'est la machine qui devine

Une salle accueille deux joueurs. À chaque manche, un mot est tiré parmi 345 ; les deux dessinent, l'IA regarde les dessins et tente de reconnaître le mot. Un point par mot reconnu, sept mots par partie, un classement des meilleurs joueurs.

Trois contraintes : le temps réel entre deux navigateurs, une inférence assez rapide pour répondre pendant qu'on dessine, et un modèle qui tolère des dessins vraiment mauvais.

[02] // ARCHITECTURE

Django, Channels et un serveur ASGI

  • Backend : Python 3.10, Django, Django Channels pour les websockets, Daphne comme serveur ASGI. Chaque salle est un groupe Channels : les traits d'un joueur sont diffusés à l'autre.
  • Frontend : HTML, CSS, JavaScript et p5.js pour la zone de dessin.
  • Données : SQLite pour les utilisateurs, les salles actives et les points. Treize migrations, dont trois pour refaire le modèle des victoires : la table Victories a fini remplacée par Points.
  • Sessions : décorateurs maison login / logout sur les routes.

[03] // LE MODÈLE

Un classifieur TFLite, et surtout du prétraitement

Le modèle est un classifieur d'images TensorFlow Lite à 345 étiquettes, embarqué dans l'application et chargé par tf.lite.Interpreter. Le vrai travail est avant l'inférence : un dessin brut envoyé en base64 ne ressemble pas à ce que le modèle a appris.

  • Conversion en niveaux de gris, inversion, binarisation au seuil 128.
  • Détection des traits par skimage.measure.find_contours, puis boîte englobante de tous les traits.
  • Recadrage sur cette boîte : un petit dessin dans un coin devient un dessin plein cadre.
  • Redimensionnement en 28 × 28, tenseur float32 de forme (1, 28, 28, 1).

[04] // BOUCLE DE JEU

Sept mots, un point par mot

  • Le serveur tire sept mots dans le pool de 345 et les envoie à la salle.
  • Pendant que les joueurs dessinent, les traits sont envoyés par websocket ; l'IA est interrogée sur l'image courante.
  • Si la prédiction correspond au mot, le joueur marque un point et la manche suivante démarre.
  • À la fin, les points sont enregistrés et le classement mis à jour.

[05] // CE QUE J'EN RETIENS

Le temps réel, c'est de la plomberie

  • Les websockets coûtent plus en gestion d'état (qui est dans quelle salle, qui est parti) qu'en code réseau : d'où le champ id_user_left dans les salles actives.
  • Un modèle moyen avec un bon prétraitement bat un bon modèle avec des entrées sales.
  • 345 classes pour un jeu, c'est beaucoup : un pool plus petit de mots faciles à dessiner rendrait les parties plus satisfaisantes.
